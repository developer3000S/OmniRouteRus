# 🗜️ Руководство по сжатию запросов — OmniRoute

> Экономьте 15-95% токенов на подходящем контексте автоматически. Для краткого обзора см. [раздел сжатия запросов в README](../README.md#%EF%B8%8F-prompt-compression--save-15-95-eligible-tokens-automatically).

## Обзор

OmniRoute реализует модульный конвейер сжатия запросов, который работает **проактивно** до того, как запросы достигают поставщиков. Это означает, что ваши экономии токенов происходят прозрачно — не требуется изменять ваш рабочий процесс.

```
Запрос клиента
  → Селектор стратегий сжатия
    → Переопределение комбинации? → Использовать настройку комбинации
    → Автоматический порог? → Использовать автоматический режим
    → Режим по умолчанию? → Использовать глобальную настройку
    → Выключено? → Пропустить сжатие
  → Выбранный режим сжатия
    → Выключено: Нет сжатия
    → Lite: Безопасная очистка пробелов/форматирования (~15%)
    → Стандартный: Удаление лишних слов и фраз (~30%)
    → Агрессивный: Устаревание истории + суммаризация (~50%)
    → Ultra: Эвристическое удаление + сжатие блоков кода (~75%)
    → RTK: Фильтрация командных выводов терминала/инструментов (60-90% диапазон)
    → Stacked: Упорядоченный конвейер из нескольких движков, обычно RTK затем Caveman (78-95% диапазон)
  → Сжатый запрос → Поставщик
```

## Режимы сжатия

### Выключено

Сжатие не применяется. Все сообщения передаются без изменений.

### Lite Mode (~15% экономии, <1ms задержка)

Самый безопасный режим — нет изменений в семантике, только очистка форматирования:

| Техника                | Описание                                       |
| ------------------------ | ------------------------------------------------- |
| `collapseWhitespace`     | Объединяет последовательные пустые строки и пробелы в конце |
| `dedupSystemPrompt`      | Удаляет дублирующиеся системные сообщения                  |
| `compressToolResults`    | Сжимает подробные выходные данные инструментов/функций            |
| `removeRedundantContent` | Удаляет повторяющиеся инструкции                       |
| `replaceImageUrls`       | Укорачивает данные изображений в формате base64                    |

**Лучше всего подходит для:** Постоянного использования, рабочих процессов с высокой безопасностью.

### Стандартный режим (~30% экономии)

Вдохновлено [Caveman](https://github.com/JuliusBrussee/caveman) — удаляет лишние слова и фразы, сохраняя при этом смысл:

- Удаляет лишние слова ("пожалуйста", "я думаю", "в общем", "на самом деле")
- Сжимает длинные фразы ("в целях" → "для", "в результате" → "потому что")
- Удаляет вежливые уступки ("Не могли бы вы...", "Если бы вы могли...")
- 30+ регулярных выражений, настроенных для кодирования запросов

**Лучше всего подходит для:** Ежедневных рабочих процессов с кодированием, команд, ориентированных на экономию.

### Агрессивный режим (~50% экономии)

Умное управление историей для длительных сессий:

- **Устаревание сообщений** — старые сообщения постепенно сжимаются
- **Суммаризация результатов инструментов** — длинные выходные данные инструментов заменяются суммаризациями
- **Гаранты целостности структуры** — обеспечивает, что пары `tool_use` + `tool_result` остаются согласованными
- **Осведомленность о окне контекста** — учитывает ограничения токенов для каждой модели

**Лучше всего подходит для:** Продолжительных отладочных сессий, больших кодовых баз.

### Ultra Mode (~75% экономии)

Максимальное сжатие для сценариев с критическим ограничением токенов:

- **Эвристическое удаление** — удаляет сообщения ниже порога релевантности
- **Сжатие блоков кода** — сжимает повторяющиеся примеры кода
- **Усечение с помощью бинарного поиска** — находит оптимальную точку усечения для окна контекста
- Включает все функции агрессивного режима

**Лучше всего подходит для:** Когда вы повторно достигаете ограничений контекста.

### RTK Mode (60-90% диапазон)

Режим RTK оптимизирован для подробных выходных данных инструментов, которые появляются в сессиях кодирующих агентов:

- Обнаруживает классы команд/выводов, такие как `git status`, `git diff`, `git log`, тестовые раннеры,
  сборки TypeScript/Vite/Webpack, ESLint/Biome/Prettier, npm audit/installs, логи Docker, инфраструктурные
  выходные данные и общий вывод оболочки
- Применяет наборы фильтров JSON из `open-sse/services/compression/engines/rtk/filters/`
- Включает 49 встроенных фильтров с образцами проверки встроенными
- Удаляет последовательности управления ANSI, индикаторы прогресса, повторяющиеся строки и недействительный шум
- Сохраняет ошибки, предупреждения, измененные файлы, суммаризации и хвост длинных выходных данных
- Поддерживает фильтры проектов с доверием, глобальные фильтры и необязательное восстановление необработанных выходных данных

**Лучше всего подходит для:** Сессий агентов с транскриптами оболочки, сборки, тестирования, git, grep и выходных данных файлов.

### Stacked Mode (78-95% диапазон)

Stacked mode запускает несколько движков сжатия в определенном порядке. Конвейер по умолчанию:

```txt
RTK -> Caveman
```

Этот порядок сначала сжимает выходные данные терминала/инструментов, а затем применяет Caveman для конденсации оставшегося естественного языка. Конвейеры Stacked могут быть настроены глобально или через комбинации сжатия, назначенные комбинациям маршрутизации.

**Лучше всего подходит для:** Смешанного контекста с большими логами инструментов плюс инструкции человека или суммаризации ассистента.

## Математика сбережений входящих данных

OmniRoute документирует сбережения сжатия из двух источников: бенчмарков входящих проектов и
собственной композиции движка OmniRoute.

| Источник | Используемое здесь число из README входящего проекта                                                                                      |
| ------- | --------------------------------------------------------------------------------------------------------------------- |
| Caveman | `~75%` меньше выходных токенов, `65%` среднее сбережение выходных данных, диапазон `22-87%`, и `~46%` сжатие входных данных |
| RTK     | `60-90%` сбережений выходных данных команд; пример сессии `~118,000 -> ~23,900` токенов, или `79.7%` сбережено (`~80%`)               |

Для перекрывающихся полезных нагрузок инструментов/контекста, комбинация по умолчанию OmniRoute складывает движки:

```txt
RTK -> Caveman
```

Общие сбережения являются умножительными, а не аддитивными:

```txt
combined = 1 - (1 - RTK savings) * (1 - Caveman input savings)
average  = 1 - (1 - 0.80) * (1 - 0.46) = 89.2%
range    = 1 - (1 - 0.60..0.90) * (1 - 0.46) = 78.4-94.6%
```

Это число `78-95%` применяется, когда и RTK, и Caveman могут уменьшить одну и ту же входную/контекстную полезную нагрузку.
Режим вывода ответа Caveman отделен: при включении используйте собственные сбережения вывода Caveman (`65%`
среднее, `~75%` заголовок, диапазон `22-87%`). Общие сбережения зависят от вашего соотношения запроса/вывода.

## Визуализация сбережений токенов

```
Без сжатия: 47K токенов отправлено в LLM
С Lite:           40K токенов отправлено          (15% сбережено — безопасно, всегда включено)
С Standard:       33K токенов отправлено          (30% сбережено — правила caveman-speak)
С Aggressive:     24K токенов отправлено          (50% сбережено — устаревание + суммаризация)
С Ultra:          12K токенов отправлено          (75% сбережено — эвристическое удаление)
С RTK:            19K-5K токенов отправлено       (60-90% сбережено на выводе команд/инструментов)
С Stacked:        10K-2.5K токенов отправлено     (78-95% диапазон RTK+Caveman)
```

## Конфигурация

### Панель управления

Перейдите в `Dashboard → Context & Cache`:

- **Caveman** — выбор режима, языковые пакеты, предпросмотр и глобальные настройки по умолчанию
- **RTK** — предпросмотр фильтра команд, настройки безопасности RTK и каталог фильтров
- **Compression Combos** — именованные конвейеры движков, назначенные комбинациям маршрутизации
- **Auto-Trigger Threshold** — автоматически включать сжатие, когда количество токенов превышает порог

### Переопределение на уровне комбинации

В `Dashboard → Context & Cache → Compression Combos` назначьте компрессионную комбинацию комбинации маршрутизации:

```txt
Combo: "free-forever"
  Compression Combo: "coding-agent-stack"
  Pipeline: RTK -> Caveman
  Targets:
    1. gc/gemini-3-flash
    2. if/kimi-k2-thinking
```

Это позволяет использовать сложенное сжатие на бесплатных/кодинговых провайдерах, сохраняя режим lite на платных подписках.

### API

```bash
# Получить настройки сжатия
curl http://localhost:20128/api/settings/compression

# Обновить настройки сжатия
curl -X PUT http://localhost:20128/api/settings/compression \
  -H "Content-Type: application/json" \
  -d '{"defaultMode":"stacked","autoTriggerMode":"stacked","autoTriggerTokens":32000}'

# Предпросмотр конкретной полезной нагрузки RTK/stacked
curl -X POST http://localhost:20128/api/compression/preview \
  -H "Content-Type: application/json" \
  -d '{"mode":"rtk","messages":[{"role":"tool","content":"npm test output here"}]}'

# Список пакетов фильтров RTK
curl http://localhost:20128/api/context/rtk/filters

# Прямое тестирование RTK с необязательными метаданными команды
curl -X POST http://localhost:20128/api/context/rtk/test \
  -H "Content-Type: application/json" \
  -d '{"command":"npm test","text":"FAIL tests/example.test.ts\nError: boom"}'
```

## Что Защищено

Движок сжатия **всегда сохраняет:**

- ✅ Блоки кода (огражденные и встроенные)
- ✅ URL-адреса и пути к файлам
- ✅ Структуры JSON и структурированные данные
- ✅ Идентификаторы и защищенные технические токены
- ✅ Математические выражения
- ✅ Определения вызовов инструментов/функций
- ✅ Системные подсказки (в режиме lite)

RTK raw-output recovery редактирует общие API-ключи, токены bearer, токены Slack, ключи доступа AWS,
пароли, токены и секреты перед тем, как что-либо будет сохранено.

## Статистика Сжатия

Каждый сжатый запрос включает статистику в журналы сервера:

```json
{
  "originalTokens": 47200,
  "compressedTokens": 40120,
  "savingsPercent": 15.0,
  "techniquesUsed": ["collapseWhitespace", "dedupSystemPrompt"],
  "mode": "lite",
  "engine": "caveman",
  "compressionComboId": "coding-agent-stack",
  "durationMs": 0.8,
  "rtkRawOutputPointers": []
}
```

## Благодарности

Правила сжатия в стандартном режиме вдохновлены **[Caveman](https://github.com/JuliusBrussee/caveman)** от **[JuliusBrussee](https://github.com/JuliusBrussee)** (⭐ 51K+) — виральным проектом "почему использовать много токенов, когда мало токенов могут обойтись". Caveman сообщает о `~75%` меньшем количестве выходных токенов, `65%` средних показателей экономии выходных данных, диапазоне выходных данных `22-87%` и `~46%` сжатия входных данных.

Режим RTK вдохновлен **[RTK - Rust Token Killer](https://github.com/rtk-ai/rtk)** от **[RTK AI](https://github.com/rtk-ai)** — проектом высокопроизводительного сжатия выходных данных команд для терминала, сборки, тестирования, фильтрации вывода git и инструментов. RTK сообщает о показателях экономии `60-90%`, с примером сессии в README, показывающей `~80%` сэкономленных данных.
