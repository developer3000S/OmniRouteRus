## 🎯 Применение

### Случай 1: "У меня есть подписка на Claude Pro"

**Проблема:** Квота истекает неиспользованной, ограничения скорости во время интенсивного кодирования

```
Комбинация: "maximize-claude"
  1. cc/claude-opus-4-7        (полностью используйте подписку)
  2. glm/glm-4.7               (дешевый резервный вариант, когда квота закончилась)
  3. if/kimi-k2       (бесплатный резервный вариант в случае экстренной ситуации)

Ежемесячная стоимость: $20 (подписка) + ~$5 (резерв) = $25 всего
против $20 + достижение лимитов = разочарование
```

### Случай 2: "Я хочу нулевую стоимость"

**Проблема:** Не могу позволить себе подписки, нужна надежная AI-поддержка для кодирования

```
Комбинация: "free-forever"
  1. gemini-cli/gemini-3-flash-preview  (180K бесплатно в месяц)
  2. if/kimi-k2       (неограниченно бесплатно)
  3. qw/qwen3-coder-plus       (неограниченно бесплатно)

Ежемесячная стоимость: $0
Качество: Модели, готовые к производству
```

### Случай 3: "Мне нужно кодирование 24/7, без перерывов"

**Проблема:** Сроки, не могу позволить себе простои

```
Комбинация: "always-on"
  1. cc/claude-opus-4-7        (лучшее качество)
  2. cx/gpt-5.5                (вторая подписка)
  3. glm/glm-4.7               (дешевый, сбрасывается ежедневно)
  4. minimax/MiniMax-M2.1      (самый дешевый, сброс через 5 часов)
  5. if/kimi-k2       (бесплатный неограниченный)

Результат: 5 уровней резерва = нулевые простои
Ежемесячная стоимость: $20-200 (подписки) + $10-20 (резерв)
```

### Случай 4: "Я хочу БЕСПЛАТНЫЙ AI в OpenClaw"

```
## 🔧 Интеграция с CLI

### Cursor IDE

```

Настройки → Модели → Расширенные:
OpenAI API Base URL: http://localhost:20128/v1
OpenAI API Key: [из панели управления omniroute]
Модель: cc/claude-opus-4-7

````

### Claude Code

Отредактируйте `~/.claude/settings.json`:

```json
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://localhost:20128",
    "ANTHROPIC_AUTH_TOKEN": "ваш-api-ключ-omniroute"
  }
}
````

Используйте корневой конечный пункт, совместимый с Claude. Не добавляйте `/v1` к `ANTHROPIC_BASE_URL`.

### Codex CLI

```bash
export OPENAI_BASE_URL="http://localhost:20128"
export OPENAI_API_KEY="ваш-api-ключ-omniroute"
codex "ваш запрос"
```

### OpenClaw

Отредактируйте `~/.openclaw/openclaw.json`:

```json
{
  "agents": {
    "defaults": {
      "model": { "primary": "omniroute/if/kimi-k2" }
    }
  },
  "models": {
    "providers": {
      "omniroute": {
        "baseUrl": "http://localhost:20128/v1",
        "apiKey": "ваш-api-ключ-omniroute",
        "api": "openai-completions",
        "models": [{ "id": "if/kimi-k2", "name": "kimi-k2" }]
      }
    }
  }
}
```

**Или используйте Панель управления:** Инструменты CLI → OpenClaw → Авто-конфигурация

### Cline / Continue / RooCode

```
Поставщик: OpenAI Compatible
Base URL: http://localhost:20128/v1
API Key: [из панели управления]
Модель: cc/claude-opus-4-7
```

## 🚀 Развертывание

### Глобальная установка npm (Рекомендуется)

```bash
npm install -g omniroute

# Создать директорию конфигурации
mkdir -p ~/.omniroute

# Создать файл .env (см. .env.example)
cp .env.example ~/.omniroute/.env

# Запустить сервер
omniroute
# Или с пользовательским портом:
omniroute --port 3000
```

CLI автоматически загружает `.env` из `~/.omniroute/.env` или `./.env`.

### Удаление

Когда вам больше не нужен OmniRoute, мы предоставляем два быстрых скрипта для чистого удаления:

| Команда                  | Действие                                                                                |
| ------------------------ | --------------------------------------------------------------------------------------- |
| `npm run uninstall`      | Удаляет системное приложение, но **сохраняет вашу БД и конфигурации** в `~/.omniroute`. |
| `npm run uninstall:full` | Удаляет приложение И **навсегда удаляет все конфигурации, ключи и базы данных**.        |

> Примечание: Для выполнения этих команд перейдите в папку проекта OmniRoute (если вы его клонировали) и выполните их. Или, если глобально установлено, просто выполните `npm uninstall -g omniroute`.

### Развертывание на VPS

```bash
git clone https://github.com/diegosouzapw/OmniRoute.git
cd OmniRoute && npm install && npm run build

export JWT_SECRET="ваш-защищенный-секрет-измените-это"
export INITIAL_PASSWORD="ваш-пароль"
export DATA_DIR="/var/lib/omniroute"
export PORT="20128"
export HOSTNAME="0.0.0.0"
export NODE_ENV="production"
export NEXT_PUBLIC_BASE_URL="http://localhost:20128"
export API_KEY_SECRET="секрет-api-ключа-конечной-точки-прокси"

npm run start
# Или: pm2 start npm --name omniroute -- start
```

### Развертывание с PM2 (Низкое потребление памяти)

Для серверов с ограниченным объемом оперативной памяти используйте опцию ограничения памяти:

```bash
# С ограничением 512MB (по умолчанию)
pm2 start npm --name omniroute -- start

# Или с пользовательским ограничением памяти
OMNIROUTE_MEMORY_MB=512 pm2 start npm --name omniroute -- start

# Или используя ecosystem.config.js
pm2 start ecosystem.config.js
```

Создайте `ecosystem.config.js`:

```javascript
module.exports = {
  apps: [
    {
      name: "omniroute",
```

Примечания:

- OpenRouter и провайдеры, совместимые с OpenAI/Anthropic, управляются только из **Доступных моделей**. Ручное добавление, импорт и автоматическая синхронизация всех попадают в один и тот же список доступных моделей, поэтому для этих провайдеров нет отдельного раздела Пользовательские модели.
- Раздел **Пользовательские модели** предназначен для провайдеров, которые не предоставляют управляемый импорт доступных моделей.

### Быстрый туннель Cloudflare

- Доступно в **Панель управления → Конечные точки** для развертывания Docker и других самоподдерживаемых развертываний
- Создает временный `https://*.trycloudflare.com` URL, который перенаправляет на ваш текущий конечный `/v1` OpenAI-совместимый
- Сначала включение устанавливает только `cloudflared`, когда это необходимо; позже перезапуски повторно используют тот же управляемый двоичный файл
- Быстрые туннели не восстанавливаются автоматически после перезапуска OmniRoute или контейнера; повторно включите их из панели управления, когда это необходимо
- URL-адреса туннелей являются временными и меняются каждый раз, когда вы останавливаете/запускаете туннель
- Управляемые быстрые туннели по умолчанию используют транспорт HTTP/2, чтобы избежать шумных предупреждений буфера QUIC UDP в ограниченных контейнерах
- Установите `CLOUDFLARED_PROTOCOL=quic` или `auto`, если вы хотите переопределить управляемый выбор транспорта
- Установите `CLOUDFLARED_BIN`, если вы предпочитаете использовать предварительно установленный двоичный файл `cloudflared` вместо управляемой загрузки
- Панель Cloudflare Quick Tunnel, Tailscale Funnel и ngrok Tunnel можно показывать или скрывать в **Настройки → Внешний вид**. Скрытие панели не останавливает работающий туннель.

### Интеллектуальный шлюз LLM (Фаза 9)

- **Семантический кэш** — Автоматически кэширует не потоковые, температура=0 ответы (обойти с помощью `X-OmniRoute-No-Cache: true`)
- **Идемпотентность запросов** — Устраняет дублирование запросов в течение 5 секунд через заголовок `Idempotency-Key` или `X-Request-Id`
- **Отслеживание прогресса** — Опциональные события SSE `event: progress` через заголовок `X-OmniRoute-Progress: true`

| **Тестер чата**      | Отправьте живые сообщения чата через прокси и проверьте полный цикл запроса/ответа             |
| **Тестовый стенд**   | Запустите пакетные тесты по нескольким комбинациям форматов для проверки правильности перевода |
| **Живой монитор**    | Смотрите переводы в реальном времени по мере прохождения запросов через прокси                 |

**Примеры использования:**

- Отладка, почему конкретная комбинация клиент/провайдер не работает
- Проверка, переводятся ли правильно теги мышления, вызовы инструментов и системные подсказки
- Сравнение различий форматов между OpenAI, Claude, Gemini и форматами API Responses

### Стратегии маршрутизации

Настройте через **Панель управления → Настройки → Маршрутизация**. Панель управления предоставляет шесть наиболее используемых стратегий; комбо и авто-маршрутизатор внутренне поддерживают более широкий набор.

**Стратегии, видимые в панели управления (маршрутизация на уровне учетной записи):**

| Стратегия                      | Описание                                                                                                                           |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| **Заполнить первым**           | Использует учетные записи в порядке приоритета — первичная учетная запись обрабатывает все запросы до тех пор, пока она недоступна |
| **Round Robin**                | Циклически перебирает все учетные записи с настраиваемым лимитом привязки (по умолчанию: 3 вызова на учетную запись)               |
| **P2C (Power of Two Choices)** | Выбирает 2 случайные учетные записи и маршрутизирует к более здоровой — балансирует нагрузку с учетом состояния здоровья           |
| **Случайный**                  | Случайным образом выбирает учетную запись для каждого запроса с использованием перемешивания Фишера-Йейтса                         |
| **Наименее используемый**      | Маршрутизирует к учетной записи с самым старым `lastUsedAt` временной меткой, распределяя трафик равномерно                        |
| **Оптимизирован по стоимости** | Маршрутизирует к учетной записи с наименьшим значением приоритета, оптимизируя для провайдеров с наименьшей стоимостью             |

**Расширенные стратегии комбо и авто** (настраиваются на уровне комбо или через префиксы `auto/*` — см. [AUTO-COMBO.md](../routing/AUTO-COMBO.md)):

- `priority` — строгий порядок, никогда не round-robins
- `weighted` — пропорциональное распределение трафика по весам на модель
- `fill-first` — исчерпывает первую модель до достижения лимитов
- `round-robin` / `strict-random` / `random`
- `p2c` (Power of Two Choices)
- `least-used` и `cost-optimized`
- `auto` — оценка по всем кандидатам
- `lkgp` (Last Known Good Provider) — привязывается к последней успешной модели за сессию
- `context-optimized` — выбирает модель с самым большим свободным окном контекста
- `context-relay` — цепочка моделей с длинным контекстом для последующих ходов

#### Внешний заголовок привязки сессии

Для внешней привязки сессии (например, агенты Claude Code/Codex за обратными прокси), отправьте:

```http
X-Session-Id: your-session-key
```

OmniRoute также принимает `x_session_id` и возвращает эффективный ключ сессии в `X-OmniRoute-Session-Id`.

Если вы используете Nginx и отправляете заголовки с подчеркиванием, включите:

```nginx
underscores_in_headers on;
```

#### Псевдонимы моделей с подстановочными знаками

Создайте шаблоны с подстановочными знаками для переназначения имен моделей:

```
Шаблон: claude-sonnet-*     →  Целевой: cc/claude-sonnet-4-6
Шаблон: gpt-*               →  Целевой: gh/gpt-5.3-codex
```

Подстановочные знаки поддерживают `*` (любые символы) и `?` (один символ).

#### Цепочки резервного копирования

Определите глобальные цепочки резервного копирования, которые применяются ко всем запросам:

```
Цепочка: production-fallback
  1. cc/claude-opus-4-7
  2. gh/gpt-5.3-codex
  3. glm/glm-4.7
```

### Устойчивость и предохранители

Настройте через **Панель управления → Настройки → Устойчивость**.

OmniRoute реализует устойчивость на уровне провайдера с пятью компонентами:

1. **Очередь запросов и темп** — Системное формирование запросов:
   - **Запросов в минуту (RPM)** — Максимальное количество запросов в минуту на учетную запись
   - **Минимальное время между запросами** — Минимальный интервал в миллисекундах между запросами
   - **Максимальное количество одновременных запросов** — Максимальное количество одновременных запросов на учетную запись

2. **Охлаждение соединения** — Настройка на уровне типа аутентификации для одного соединения после повторяемых сбоев:
   - **Базовое охлаждение** — Окно охлаждения по умолчанию для повторяемых сбоев на стороне поставщика
   - **Использовать подсказки повторной попытки на стороне поставщика** — Учитывает авторитетные `Retry-After` или подсказки сброса, когда они предоставлены
   - **Максимальное количество шагов обратного отсчета** — Максимальный уровень экспоненциального обратного отсчета для повторяющихся сбоев

3. **Предохранитель провайдера** — Отслеживает сбои на уровне провайдера и автоматически открывает предохранитель, когда достигается заданный порог:
   - **Порог сбоя** — Последовательные сбои провайдера перед открытием предохранителя
   - **Тайм-аут сброса** — Время ожидания перед повторной проверкой провайдера
   - **ЗАКРЫТ** (Здоровый) — Запросы проходят нормально
   - **ОТКРЫТ** — Провайдер временно заблокирован после повторяющихся сбоев
   - **ПОЛУОТКРЫТ** — Проверка, восстановился ли провайдер

   Соединение-специфические `429` ограничения скорости остаются в **Охлаждении соединения** и не учитываются в предохранителе провайдера.

   Состояние времени выполнения предохранителя провайдера отображается только на **Панели управления → Здоровье**.

4. **Ожидание охлаждения** — Если все кандидаты соединения уже охлаждаются, OmniRoute может подождать самого раннего охлаждения и автоматически повторить тот же клиентский запрос.

5. **Автоматическое обнаружение ограничения скорости** — При возврате провайдерами явных окон ожидания эти подсказки переопределяют локальное охлаждение соединения, когда эта настройка включена.

**Совет:** Используйте страницу **Здоровье**, чтобы просмотреть и сбросить работающие предохранители провайдера после сбоя. Страница Устойчивости изменяет только конфигурацию.

### Экспорт / Импорт базы данных

Управляйте резервными копиями базы данных в **Панель управления → Настройки → Система и хранилище**.

| Действие                    | Описание                                                                                                                                                  |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Экспорт базы данных**     | Скачивает текущую базу данных SQLite в виде файла `.sqlite`                                                                                               |
| **Экспорт всего (.tar.gz)** | Скачивает полный архив резервной копии, включая: базу данных, настройки, комбо, соединения с провайдерами (без учетных данных), метаданные API-ключей     |
| **Импорт базы данных**      | Загрузите файл `.sqlite`, чтобы заменить текущую базу данных. Автоматическая резервная копия создается до импорта, если `DISABLE_SQLITE_AUTO_BACKUP=true` |

```bash
# API: Экспорт базы данных
curl -o backup.sqlite http://localhost:20128/api/db-backups/export

# API: Экспорт всего (полный архив)
curl -o backup.tar.gz http://localhost:20128/api/db-backups/exportAll

# API: Импорт базы данных
curl -X POST http://localhost:20128/api/db-backups/import \
  -F "file=@backup.sqlite"
```

**Проверка импорта:** Импортируемый файл проверяется на целостность (проверка прагмы SQLite), наличие обязательных таблиц (`provider_connections`, `provider_nodes`, `combos`, `api_keys`) и размер (максимум 100 МБ).

**Примеры использования:**

- Перенос OmniRoute между машинами
- Создание внешних резервных копий для восстановления после сбоев
- Обмен конфигурациями между членами команды (экспорт всего → общий архив)

### Стратегии балансировки комбо

## 🤖 Авто-маршрутизация (Zero-config)

OmniRoute поставляется с **авто-маршрутизатором на основе оценки**, который выбирает лучшую модель для каждого запроса среди всех подключенных провайдеров — без необходимости поддерживать комбо. Просто отправьте запрос с одним из префиксов `auto/*`, и OmniRoute соберет виртуальное комбо на лету, оценивая кандидатов по таким параметрам, как задержка, стоимость, процент успешных запросов, соответствие контексту, пригодность модели для задачи, недавние сбои, квоты и состояние цепей отключения.

| Префикс        | Оптимизирует для                                                                               |
| -------------- | ---------------------------------------------------------------------------------------------- |
| `auto`         | Сбалансированный по умолчанию (задержка × стоимость × процент успешных запросов)               |
| `auto/coding`  | Задачи по программированию: предпочитает Claude, GPT-5, GLM, Kimi, Qwen Coder, DeepSeek coders |
| `auto/cheap`   | Наименьшая стоимость за токен, допускает большую задержку                                      |
| `auto/fast`    | Наименьшая задержка, игнорирует стоимость                                                      |
| `auto/offline` | Локальные провайдеры (Ollama, vLLM, llama.cpp) — полезно для установок без доступа к интернету |
| `auto/smart`   | Качество рассуждений в первую очередь (Opus, GPT-5 xhigh, R1, GLM 5.1 reasoning)               |
| `auto/lkgp`    | "Последний известный хороший провайдер" — привязан к последнему успешно выполненному запросу   |

Пример:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/coding",
    "messages": [{ "role": "user", "content": "Рефакторинг этой Python функции" }],
    "stream": true
  }'
```

Авто-маршрутизатор полностью описан в [AUTO-COMBO.md](../routing/AUTO-COMBO.md) — включая настройку весов оценки, черный список провайдеров и просмотр решений маршрутизации в **Dashboard → Auto Combo**.

## 🔌 Интеграция MCP & A2A

OmniRoute является как **MCP-сервером** (Model Context Protocol), так и **A2A-сервером** (Agent-to-Agent JSON-RPC 2.0). Любой совместимый с MCP IDE или хост агентов может вызывать инструменты OmniRoute напрямую — без дополнительной обертки.

### Транспорты MCP

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **Streamable HTTP**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (для плагинов IDE, предпочитающих stdio)

### Подключение Claude Desktop

Отредактируйте `~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) или аналогичный файл на Windows/Linux:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### Подключение Cursor / Continue / VS Code MCP

Используйте URL SSE `http://localhost:20128/api/mcp/sse` и Bearer API-ключ, сгенерированный в **Dashboard → API Manager**.

### Области действия

Инструменты MCP сгруппированы в 10 областей: `analytics`, `auth`, `billing`, `combos`, `health`, `keys`, `memory`, `models`, `providers`, `system`. Каждый Bearer-ключ может быть ограничен определенными областями — см. [MCP-SERVER.md](../frameworks/MCP-SERVER.md) для полного каталога инструментов и [A2A-SERVER.md](../frameworks/A2A-SERVER.md) для схемы JSON-RPC.

## 💾 Система памяти

OmniRoute сохраняет **долгосрочную память бесед** с использованием гибридного извлечения:

- **SQLite FTS5** для поиска по ключевым словам в прошлых сообщениях
- **Векторное хранилище Qdrant** (опционально) для семантического поиска
- **Автоматическое извлечение фактов** — сущности, предпочтения и решения суммируются после каждой сессии и сохраняются в таблице `memory_facts`
- Память ограничена по API-ключу и сессии

Управляйте памятью в **Dashboard → Memory** (поиск, редактирование, экспорт, очистка). HTTP-интерфейс (`/api/memory/*`) позволяет агентам программно добавлять и запрашивать факты — см. [MEMORY.md](../frameworks/MEMORY.md).

## 🔔 Вебхуки

Подписывайтесь на события OmniRoute для мониторинга и автоматизации в реальном времени.

- Создайте вебхук в **Dashboard → Webhooks** с указанием целевого URL и секретного ключа HMAC
- Доступные события: `request.completed`, `request.failed`, `provider.unavailable`, `budget.exceeded`, `combo.switched`, `circuit_breaker.opened`, `circuit_breaker.closed`
- Каждый запрос содержит заголовок `X-OmniRoute-Signature` (HMAC-SHA256) для проверки подлинности
- Повторные попытки: 3 попытки с экспоненциальной задержкой, затем очередь неудачных доставок

Полная схема в [WEBHOOKS.md](../frameworks/WEBHOOKS.md).

## 🛠️ Программное управление

Вы можете управлять всеми ресурсами OmniRoute (провайдеры, комбо, ключи, настройки) через HTTP с использованием **ключа Bearer с областью `manage`**.

Сгенерируйте ключ в **Dashboard → API Manager → New Key → Scope: manage**, затем:

```bash
# Список провайдеров
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# Добавление соединения с провайдером
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# Создание комбо
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# Список/создание API-ключей
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

См. [API_REFERENCE.md](../reference/API_REFERENCE.md) для полного каталога конечных точек и схем запросов/ответов.

## 💻 Внутренний CLI

OmniRoute поставляется с внутренним CLI (`omniroute …`) для настройки, диагностики и управления в реальном времени. Это **отдельно от страницы "Инструменты CLI" в панели управления**, которая настраивает сторонние CLI (Claude Code, Cursor, Codex, Cline, …), чтобы они могли общаться с OmniRoute.

```bash
omniroute setup                    # Интерактивный мастер (пароль, провайдеры, комбинации)
omniroute setup --non-interactive  # Подходит для CI
omniroute doctor                   # Диагностика состояния (директория данных, БД, провайдеры, порты)
omniroute providers available      # Список поддерживаемых провайдеров
omniroute providers list           # Список настроенных подключений
omniroute providers test <id>      # Проверка подключения к провайдеру в реальном времени
omniroute combos list              # Список комбинаций
omniroute combos switch <name>     # Установить комбинацию по умолчанию
omniroute models                   # Список доступных моделей (--json, --search)
omniroute keys add | list | remove # Управление API-ключами из терминала
omniroute backup                   # Создать резервную копию конфигурации и БД
omniroute restore [<timestamp>]    # Восстановить из резервной копии
omniroute health                   # Детальная информация о состоянии (брейкеры, кэш, память)
omniroute quota                    # Использование квот провайдеров
omniroute mcp status               # Статус сервера MCP
omniroute a2a status               # Статус сервера A2A
omniroute tunnel list|create|stop  # Туннели Cloudflare/Tailscale/ngrok
omniroute reset-password           # Сбросить пароль администратора
omniroute --mcp                    # Запустить сервер MCP через stdio
omniroute --port 3000              # Запустить сервер на пользовательском порту
```

Совет: соедините `omniroute doctor --json` с вашим инструментом мониторинга, чтобы получать уведомления о неработающих подключениях к провайдерам.

## 🖥️ Десктопное приложение (Electron)

OmniRoute доступно как нативное десктопное приложение для Windows, macOS и Linux.

### Установка

```bash
# Из директории electron:
cd electron
npm install

# Режим разработки (подключение к запущенному серверу Next.js в режиме разработки):
npm run dev

# Режим продакшена (использует автономную сборку):
npm start
```

### Создание установщиков

```bash
cd electron
npm run build          # Текущая платформа
npm run build:win      # Windows (.exe NSIS)
npm run build:mac      # macOS (.dmg universal)
npm run build:linux    # Linux (.AppImage)
```

Вывод → `electron/dist-electron/`

### Основные функции

| Функция                            | Описание                                                            |
| ---------------------------------- | ------------------------------------------------------------------- |
| **Готовность сервера**             | Ожидание готовности сервера перед показом окна (нет пустого экрана) |
| **Системный трей**                 | Свернуть в трей, изменить порт, выйти из трей-меню                  |
| **Управление портами**             | Изменить порт сервера из трея (автоматический перезапуск сервера)   |
| **Политика безопасности контента** | Ограничительная CSP через заголовки сессии                          |
| **Единственный экземпляр**         | Только один экземпляр приложения может работать одновременно        |
| **Оффлайн-режим**                  | Встроенный сервер Next.js работает без интернета                    |

### Переменные окружения

| Переменная            | По умолчанию | Описание                               |
| --------------------- | ------------ | -------------------------------------- |
| `OMNIROUTE_PORT`      | `20128`      | Порт сервера                           |
| `OMNIROUTE_MEMORY_MB` | `512`        | Ограничение кучи Node.js (64–16384 MB) |

📖 Полная документация: [`electron/README.md`](../../electron/README.md)
