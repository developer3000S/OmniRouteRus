# Руководство по Progressive Web App (PWA)

OmniRoute поставляется как полностью устанавливаемое Progressive Web App. Когда вы открываете панель управления из любого мобильного браузера — Android (Chrome) или iOS (Safari) — вы можете "Добавить на главный экран" и получить нативный опыт приложения без необходимости использования магазина приложений.

## Что такое PWA?

Progressive Web App превращает веб-панель управления OmniRoute в что-то, что выглядит и работает как нативное мобильное приложение. После установки оно:

- Запускается с главного экрана с собственной иконкой
- Открывается на весь экран — без адресной строки браузера и интерфейса вкладок
- Работает в автономном режиме с выделенной страницей подключения
- Кэширует статические ресурсы для более быстрой загрузки
- Поддерживает как портретную, так и альбомную ориентацию

## Установка

### Android (Chrome)

1. Откройте панель управления OmniRoute в Chrome: `http://YOUR_IP:20128`
2. Chrome автоматически покажет баннер **"Добавить OmniRoute на главный экран"**, или:
   - Нажмите **⋮** (три точки) → **"Добавить на главный экран"** или **"Установить приложение"**
3. Подтвердите запрос
4. OmniRoute появится на вашем главном экране как автономное приложение

### iOS (Safari)

1. Откройте панель управления OmniRoute в Safari: `http://YOUR_IP:20128`
2. Нажмите кнопку **Share** (коробка с стрелкой)
3. Прокрутите вниз и нажмите **"Добавить на главный экран"**
4. Назовите его (по умолчанию "OmniRoute") и нажмите **Добавить**
5. OmniRoute появится на вашем главном экране с иконкой приложения

### Desktop (Chrome / Edge)

1. Откройте панель управления OmniRoute
2. Нажмите **иконку установки** в адресной строке (или ⋮ → "Установить OmniRoute...")
3. Подтвердите запрос
4. OmniRoute открывается как автономное окно — без вкладок, без адресной строки

## Особенности

### Полноэкранный опыт

Манифест настроен с `display: "fullscreen"`, что означает, что установленное приложение использует весь экран — без хром браузера, без перекрытия панели состояния. Это делает панель управления действительно нативной.

### Поддержка автономного режима

OmniRoute включает сервисный работник (`sw.js`), который обеспечивает интеллектуальное кэширование:

| Тип ресурса                                            | Стратегия                          | Поведение                                                                     |
| ------------------------------------------------------- | ---------------------------------- | ---------------------------------------------------------------------------- |
| **App Shell**                                           | Cache-first                        | `/`, `/offline`, манифест и иконки предварительно кэшируются при установке   |
| **Статические ресурсы** (CSS, JS, изображения, шрифты)  | Network-first with cache fallback | Получает свежие данные из сети; переходит к кэшу, если оффлайн               |
| **Сборки Next.js** (`/_next/`)                         | Network-first with cache update    | Получает данные из сети и обновляет кэш; отображает кэшированную версию, если оффлайн |
| **Запросы навигации**                                  | Network-only with offline fallback | Всегда получает данные из сети; отображает страницу `/offline`, если нет сети |
| **API маршруты** (`/api/`, `/a2a`, `/dashboard/endpoint`) | Bypass (never cached)              | Всегда идет напрямую к серверу — никогда не перехватывается сервисным работником |

### Страница автономного режима

Когда сеть недоступна и пользователь переходит на новую страницу, сервисный работник отображает выделенную страницу `/offline`, которая:

- Отображает четкое сообщение **"Проблема с подключением"**
- Показывает индикатор **онлайн/оффлайн**, который обновляется в реальном времени
- Предоставляет кнопку **"Повторить подключение"** для перезагрузки при восстановлении соединения
- Ссылки на **страницу статуса** для диагностики

### Иконки приложения

OmniRoute предоставляет иконки, оптимизированные для каждой платформы:

| Файл                   | Размер             | Используется для                          |
| ---------------------- | ---------------- | ------------------------------------- |
| `icon-512.png`         | 512×512          | Установка Android, заставка экрана       |
| `apple-touch-icon.png` | 180×180          | Иконка на главном экране iOS            |
| `icon-192.svg`         | 192×192 (вектор)  | Адаптивная иконка Android               |
| `apple-touch-icon.svg` | 180×180 (вектор)  | Резервная иконка Apple                  |
| `favicon.svg`          | Вектор           | Вкладки браузера                        |
| `favicon.ico`          | Многоразмерный   | Устаревшие браузеры                     |

### Автоматическая регистрация

Сервисный работник регистрируется автоматически через компонент `<PwaRegister />` в корневом макете. Для пользователя не требуется никаких действий — приложение становится устанавливаемым, как только браузер обнаруживает действительный манифест и сервисный работник.

## Техническая архитектура

### Манифест веб-приложения (`manifest.webmanifest`)

Создается Next.js через `src/app/manifest.ts`:

```json
{
  "name": "OmniRoute",
  "short_name": "OmniRoute",
  "description": "OmniRoute — это шлюз ИИ для работы с несколькими провайдерами LLM. Один конечный пункт для всех ваших провайдеров ИИ.",
  "start_url": "/",
  "scope": "/",
  "display": "fullscreen",
  "orientation": "any",
  "background_color": "#0b0f1a",
  "theme_color": "#0b0f1a",
  "icons": [
    { "src": "/icon-512.png", "sizes": "512x512", "type": "image/png", "purpose": "any maskable" },
    { "src": "/apple-touch-icon.png", "sizes": "180x180", "type": "image/png" }
  ]
}
```

### Сервисный работник (`public/sw.js`)

Обычный сервисный работник (без зависимостей от фреймворка) с:

- **Фаза установки**: Предварительно кэширует оболочку приложения (корень, страница оффлайн, манифест, иконки)
- **Фаза активации**: Очищает старые версии кэша и заявляет о всех клиентах
- **Фаза получения**: Интеллектуальное маршрутизация на основе типа запроса (навигация, статический ресурс, API)
- **Версионирование кэша**: `omniroute-pwa-v2` — увеличьте это значение, чтобы принудительно обновить кэш

### Метаданные макета (`src/app/layout.tsx`)

Корневой макет предоставляет все метатеги, необходимые для соответствия PWA:

- `manifest` ссылка на `/manifest.webmanifest`
- `apple-web-app-capable: true` для автономного режима iOS
- `apple-web-app-status-bar-style: black-translucent`
- `mobile-web-app-capable: yes` для Android Chrome
- `theme-color: #0b0f1a`
- `viewport-fit: cover` для рендеринга от края до края

### Компонент: `PwaRegister`

Находится в `src/shared/components/PwaRegister.tsx`, этот клиентский компонент:

1. Запускается при монтировании (только на стороне клиента)
2. Проверяет поддержку `serviceWorker` в браузере
3. Регистрирует `/sw.js` бесшумно (ошибки подавляются, чтобы избежать блокировки приложения)
4. Ничего не отображает (`return null`) — это компонент только для побочных эффектов

## Использование с Termux (Android)

При запуске OmniRoute на Android через Termux PWA работает без проблем:

1. Запустите OmniRoute в Termux: `npx omniroute`
2. Откройте Chrome на том же телефоне: `http://localhost:20128`
3. Установите PWA через "Добавить на главный экран"
4. PWA подключается к локальному серверу Termux — все работает на устройстве

Это сочетание означает, что ваш Android-телефон является как **сервером** (Termux), так и **клиентом** (PWA) — полноценным автономным шлюзом ИИ.

## Использование с других устройств

Установите PWA на любом устройстве, которое имеет доступ к браузеру вашего сервера OmniRoute:

- **Другой телефон/планшет**: Перейдите по адресу `http://PHONE_IP:20128` и установите PWA
- **Ноутбук**: Откройте Chrome/Edge и установите его как настольное PWA
- **Смарт-телевизор с браузером**: Доступ к панели управления в полноэкранном режиме

## Настройка

### Название экземпляра

Заголовок PWA учитывает настройку **Instance Name** из `Dashboard → Settings`. Если вы переименуете свой экземпляр в "My AI Gateway", установленный PWA будет отображать это имя.

### Пользовательский значок

Если вы загрузите пользовательский значок через `Dashboard → Settings`, значок PWA на рабочем столе отобразит пользовательский значок. Значки домашнего экрана мобильных устройств используют предварительно созданные файлы `icon-512.png` и `apple-touch-icon.png`.

## Ограничения

- **Нет push-уведомлений** — сервисный работник не реализует Push API. Уведомления обрабатываются приложением Electron вместо этого.
- **Нет фоновой синхронизации** — действия в автономном режиме не помещаются в очередь для повторного воспроизведения. PWA в основном является просмотрщиком дашборда.
- **Ограничения iOS** — Safari на iOS не поддерживает все функции PWA (например, приглашения установки вручную, а также ограниченные фоновые сервисные работники).
- **Размер кэша** — сервисный работник кэширует только статические ресурсы. Большие полезные нагрузки ответов из маршрутов `/api/` никогда не кэшируются.
- **Пользовательские иконки на мобильных устройствах** — изменение фавикона в настройках не обновляет иконку на домашнем экране мобильного устройства (это требует повторной генерации иконок PWA).
