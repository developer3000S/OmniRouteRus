## Завершения чата

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Напишите функцию для..."}
  ],
  "stream": true
}
```

### Пользовательские заголовки

| Заголовок                | Направление | Описание                                                 |
| ------------------------ | ----------- | -------------------------------------------------------- |
| `X-OmniRoute-No-Cache`   | Запрос      | Установите `true`, чтобы обойти кэш                      |
| `X-OmniRoute-Progress`   | Запрос      | Установите `true` для событий прогресса                  |
| `X-Session-Id`           | Запрос      | Ключ липкой сессии для внешней сессии                    |
| `x_session_id`           | Запрос      | Вариант с подчеркиванием также принимается (прямой HTTP) |
| `Idempotency-Key`        | Запрос      | Ключ для дедупликации (окно 5с)                          |
| `X-Request-Id`           | Запрос      | Альтернативный ключ для дедупликации                     |
| `X-OmniRoute-Cache`      | Ответ       | `HIT` или `MISS` (не для потоковой передачи)             |
| `X-OmniRoute-Idempotent` | Ответ       | `true`, если дедуплицировано                             |
| `X-OmniRoute-Progress`   | Ответ       | `enabled`, если отслеживание прогресса включено          |
| `X-OmniRoute-Session-Id` | Ответ       | Идентификатор сессии, используемый OmniRoute             |

> Примечание Nginx: если вы используете заголовки с подчеркиванием (например, `x_session_id`), включите `underscores_in_headers on;`.

## Вложения

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "Еда была вкусной"
}
```

```bash
# Список всех моделей вложений

```

## Совместимые конечные точки

| Метод | Путь                        | Формат                                 |
| ----- | --------------------------- | -------------------------------------- |
| POST  | `/v1/chat/completions`      | OpenAI                                 |
| POST  | `/v1/messages`              | Anthropic                              |
| POST  | `/v1/responses`             | OpenAI Responses                       |
| POST  | `/v1/embeddings`            | OpenAI                                 |
| POST  | `/v1/images/generations`    | OpenAI Images                          |
| POST  | `/v1/images/edits`          | OpenAI Images (редактирование/инпайнт) |
| POST  | `/v1/videos/generations`    | Генерация видео в стиле OpenAI         |
| POST  | `/v1/music/generations`     | Генерация музыки в стиле OpenAI        |
| POST  | `/v1/audio/transcriptions`  | OpenAI Audio (STT)                     |
| POST  | `/v1/audio/speech`          | OpenAI TTS (возвращает тело аудио)     |
| POST  | `/v1/rerank`                | Cohere/Voyage-style rerank             |
| POST  | `/v1/moderations`           | OpenAI Moderations                     |
| GET   | `/v1/models`                | OpenAI                                 |
| POST  | `/v1/messages/count_tokens` | Anthropic                              |
| GET   | `/v1beta/models`            | Gemini                                 |
| POST  | `/v1beta/models/{...path}`  | Gemini generateContent                 |
| POST  | `/v1/api/chat`              | Ollama                                 |

Все POST-маршруты следуют одной форме: `Bearer your-api-key` + валидированное JSON-тело (например, `v1RerankSchema`, `v1ModerationSchema`, `v1AudioSpeechSchema` и т.д., см. `src/shared/validation/schemas.ts`). Возвращается `4xx` при ошибке схемы.

```bash
# Ранжирование
POST /v1/rerank      { "model": "cohere/rerank-3", "query": "...", "documents": ["..."] }

# Модерации
POST /v1/moderations { "model": "omni-moderation-latest", "input": "..." }

# TTS — возвращает тело audio/mpeg (или запрошенный формат)
POST /v1/audio/speech { "model": "openai/tts-1", "input": "Привет", "voice": "alloy" }

# Редактирование изображения (multipart)
POST /v1/images/edits  -F image=@input.png -F prompt="..." -F mask=@mask.png

# Генерация видео / музыки (идентификатор модели с префиксом провайдера)
POST /v1/videos/generations { "model": "runway/gen-3", "prompt": "..." }
POST /v1/music/generations  { "model": "suno/v3.5",   "prompt": "..." }
```

### Маршруты для конкретных провайдеров

```bash
POST /v1/providers/{provider}/chat/completions
POST /v1/providers/{provider}/embeddings
POST /v1/providers/{provider}/images/generations
```

Префикс провайдера автоматически добавляется, если он отсутствует. Несоответствующие модели возвращают `400`.

## Files API

OpenAI-совместимый файловой конечной точки для пакетной обработки ввода/вывода и загрузки файлов с указанием назначения.

| Метод  | Путь                     | Описание                                                                                                         |
| ------ | ------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| POST   | `/v1/files`              | Загрузить файл (multipart: `file`, `purpose`, `expires_after[anchor]`, `expires_after[seconds]`) — макс. 512 MiB |
| GET    | `/v1/files`              | Список файлов для аутентифицированного API ключа                                                                 |
| GET    | `/v1/files/[id]`         | Получить метаданные файла                                                                                        |
| DELETE | `/v1/files/[id]`         | Удалить файл                                                                                                     |
| GET    | `/v1/files/[id]/content` | Потоковое воспроизведение исходного тела файла обратно                                                           |

**Аутентификация:** Bearer API ключ — файлы ограничены по API-ключу через `getApiKeyRequestScope`.

## Batches API

OpenAI-совместимая пакетная обработка.

| Метод  | Путь                      | Описание                                                                                                     |
| ------ | ------------------------- | ------------------------------------------------------------------------------------------------------------ |
| POST   | `/v1/batches`             | Создать пакет — тело проверяется по `v1BatchCreateSchema` (`input_file_id`, `endpoint`, `completion_window`) |
| GET    | `/v1/batches`             | Список пакетов                                                                                               |
| GET    | `/v1/batches/[id]`        | Получить статус пакета + `request_counts`                                                                    |
| DELETE | `/v1/batches/[id]`        | Удалить завершенный/неудачный пакет                                                                          |
| POST   | `/v1/batches/[id]/cancel` | Отменить выполняющийся пакет                                                                                 |

**Аутентификация:** Bearer API ключ. Пакеты ограничены по API-ключу.

## Search API

Абстракция веб/поискового провайдера (Tavily, Brave, Exa, Serper и т.д.).

| Метод | Путь                   | Описание                                                                                                 |
| ----- | ---------------------- | -------------------------------------------------------------------------------------------------------- |
| GET   | `/v1/search`           | Список настроенных поисковых провайдеров + возможностей                                                  |
| POST  | `/v1/search`           | Выполнить поисковый запрос — тело проверяется по `v1SearchSchema`, поддерживает кэширование/согласование |
| GET   | `/v1/search/analytics` | Статистика по провайдерам (попадания/задержка/кэш)                                                       |

**Аутентификация:** Bearer API ключ (`extractApiKey` + `isValidApiKey`). Политика поиска применяется через `enforceApiKeyPolicy`.

## Веб-сокетное потоковое передача

```bash
GET /v1/ws?handshake=1
```

Проверяет обновление протокола WebSocket и возвращает примеры сообщений протокола (`request`, `cancel`). Фреймы WS обрабатываются сервером WS, встроенным в Next.js, вне таблицы маршрутов.

**Аутентификация:** Ключ API Bearer во время рукопожатия.

## Бюджет

```bash
# Получить статус бюджета для всех API-ключей
GET /api/usage/budget

# Установить или обновить бюджет
POST /api/usage/budget
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "dailyLimitUsd": 5.00,
  "weeklyLimitUsd": 30.00,
  "monthlyLimitUsd": 100.00,
  "warningThreshold": 0.8,
  "resetInterval": "monthly"
}
```

> **Примечания к схеме** (`setBudgetSchema`): `apiKeyId` обязателен; хотя бы одно из `dailyLimitUsd`, `weeklyLimitUsd` или `monthlyLimitUsd` должно быть больше нуля. Необязательные поля: `warningThreshold` (0–1), `resetInterval` (`daily` | `weekly` | `monthly`), `resetTime` (`HH:MM`). Устаревшая форма `{keyId, limit, period}` возвращает `400 Bad Request`.

## Обработка запросов

1. Клиент отправляет запрос на `/v1/*`
2. Обработчик маршрута вызывает `handleChat`, `handleEmbedding`, `handleAudioTranscription` или `handleImageGeneration`
3. Модель разрешается (прямой провайдер/модель или псевдоним/комбо)
4. Учетные данные выбираются из локальной БД с фильтрацией по доступности аккаунта
5. Для чата: `handleChatCore` проверяет семантический/сигнатурный кэш и разрешает настройки сжатия комбо
6. Прогрессивное сжатие запускается до перевода провайдера, если включено (`lite`, Caveman, RTK или стековое)
7. Исполнитель провайдера отправляет запрос вверх по потоку
8. Ответ переводится обратно в формат клиента (чат) или возвращается как есть (эмбеддинги/изображения/аудио)
9. Записываются использование, аналитика сжатия и логи запросов
10. Применяется резервное копирование при ошибках в соответствии с правилами комбо

Полная ссылка на архитектуру: [`ARCHITECTURE.md`](../architecture/ARCHITECTURE.md)

## Resilience (extended)

OmniRoute предоставляет три независимых механизма временных сбоев; следующие конечные точки управления позволяют операторам читать и переопределять их:

| Область применения  | Хранение состояния                            | Чтение                                    | Сброс / очистка                                    |
| ------------------- | --------------------------------------------- | ----------------------------------------- | -------------------------------------------------- |
| Provider breaker    | `domain_circuit_breakers` + in-memory         | `/api/monitoring/health`                  | `POST /api/resilience/reset`                       |
| Connection cooldown | `rateLimitedUntil` на соединениях провайдеров | `/api/rate-limits`, `/api/providers/[id]` | (включается лениво; очистить через PUT провайдера) |
| Model lockout       | Реестр доступности моделей в памяти           | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`           |

```bash
# Очистить блокировку одной модели
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# Очистить все блокировки
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

Полная концептуальная справка и значения по умолчанию для переключателей: см. [`CLAUDE.md`](../../CLAUDE.md) → "Resilience Runtime State".

| GET    | `/api/skills/skillssh?q=&limit=`  | Поиск в реестре skills.sh                                                                                                     |
| POST   | `/api/skills/skillssh/install`    | Установить навык по id из skills.sh                                                                                           |

**Авторизация:** сессия управления/API ключ. Маркетплейсные маршруты поиска принимают либо авторизацию управления, либо Bearer API ключ (`isAuthenticated`).

## MCP Server

OmniRoute поставляется с встроенным сервером Model Context Protocol с 3 транспортами (stdio, SSE, streamable-http) и ограниченными инструментами. Ниже приведены конечные точки панели управления, которые читают статусные/аудитные данные и проксируют HTTP транспорты.

| Метод | Путь | Описание |
| ------ | ---------------------- | ------------------------------------------------------------------------------------------------ | -------------------- |
| GET | `/api/mcp/status` | Состояние сервера, транспорт, онлайн-статус, последний вызов, топ инструментов, 24-часовой процент успешных вызовов |
| GET | `/api/mcp/tools` | Список инструментов MCP с `name`, `description`, `scopes`, `phase`, `auditLevel`, `sourceEndpoints` |
| GET | `/api/mcp/sse` | Открыть SSE поток для транспорта SSE (возвращает `503`, если MCP отключен или транспорт не совпадает) |
| POST | `/api/mcp/sse` | Отправить JSON-RPC фрейм на транспорт SSE |
| GET | `/api/mcp/stream` | Открыть SSE сторону транспорта Streamable HTTP (сообщения, инициированные сервером) |
| POST | `/api/mcp/stream` | Отправить JSON-RPC фрейм на транспорт Streamable HTTP |
| DELETE | `/api/mcp/stream` | Завершить сессию Streamable HTTP |
| GET | `/api/mcp/audit` | Запрос аудит-лога — `?limit=`, `?offset=`, `?tool=`, `?success=true|false`, `?apiKeyId=` |
| GET | `/api/mcp/audit/stats` | Агрегированная статистика аудита (общие показатели, процент успешных вызовов, средняя длительность, топ инструментов) |

**Авторизация:** транспорты `sse`/`stream` используют поверхность авторизации MCP (Bearer API ключ с `mcp` scope); маршруты `status`/`tools`/`audit*` доступны из панели управления (дополнительная авторизация не требуется).

> Оба HTTP транспорта ограничены `settings.mcpEnabled` и `settings.mcpTransport` — несовпадение транспорта возвращает `400`, отключенное состояние MCP возвращает `503`.

## A2A Server

OmniRoute предоставляет конечную точку A2A (Agent-to-Agent) JSON-RPC 2.0, а также REST-обёртку для использования в инспекции/панелях управления.

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # опционально, если не установлен OMNIROUTE_API_KEY
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Route this coding task"}]
  }
}
```

Поддерживаемые методы (все ограничены `settings.a2aEnabled`):

| Метод            | Описание                                                               |
| ---------------- | ---------------------------------------------------------------------- |
| `message/send`   | Синхронное выполнение навыка; возвращает `{task, artifacts, metadata}` |
| `message/stream` | Потоковое SSE выполнение того же набора навыков                        |
| `tasks/get`      | Получить задачу по `taskId`                                            |
| `tasks/cancel`   | Отменить задачу по `taskId`                                            |

Встроенные навыки: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`.

### Карта агента

```bash
GET /.well-known/agent.json
```

Возвращает публичную карту A2A агента (имя, описание, возможности, каталог навыков, схема аутентификации) — кэшируется публично на 1 час. Аутентификация не требуется.

### REST-помощники

| Метод | Путь                         | Описание                                                                                                          |
| ----- | ---------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| GET   | `/api/a2a/status`            | A2A включен + статистика задач + сводка кэшированной карты агента                                                 |
| GET   | `/api/a2a/tasks`             | Список задач — `?state=submitted\|working\|completed\|failed\|cancelled`, `?skill=`, `?limit=` (≤200), `?offset=` |
| POST  | `/api/a2a/tasks`             | (Не реализовано как REST-помощник — создайте через JSON-RPC `message/send`)                                       |
| GET   | `/api/a2a/tasks/[id]`        | Получить одну задачу                                                                                              |
| POST  | `/api/a2a/tasks/[id]/cancel` | Отменить задачу                                                                                                   |

**Аутентификация:** REST-помощники работают без аутентификации управления (читаемы для панели управления); JSON-RPC маршрут `/a2a` использует Bearer `OMNIROUTE_API_KEY`, если настроен.

## Аутентификация

- Маршруты Dashboard (`/dashboard/*`) используют cookie `auth_token`
- Вход в систему использует сохраненный хэш пароля; резервный вариант — `INITIAL_PASSWORD`
- `requireLogin` можно переключать через `/api/settings/require-login`
- Маршруты `/v1/*` могут требовать Bearer API ключ, если `REQUIRE_API_KEY=true`

> **Критическое изменение (v3.8.0)** — `/api/v1/agents/tasks/*` и эндпоинты управления кулдауном теперь требуют **управляющей аутентификации** (cookie `auth_token` dashboard или API ключ с правами управления). Клиенты, которые ранее вызывали эти маршруты без аутентификации, получат `401 Unauthorized`. Смотрите коммит `588a0333` (`fix(auth): require management auth for agent and cooldown APIs`).
