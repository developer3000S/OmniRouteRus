# Система геймификации и таблицы лидеров

> **Источник истины:** `src/lib/gamification/`, `src/lib/db/gamification.ts`, `src/app/api/gamification/`
> **Последнее обновление:** 2026-05-19 — v3.8.0

OmniRoute включает локальный уровень геймификации, который вознаграждает пользователей за взаимодействие с платформой — отправку запросов, переключение провайдеров, создание комбо, обмен токенами и вклад в сообщество. Все состояние хранится в SQLite; федерация с серверами сообщества является необязательной и работает по принципу push.

Система разработана для **нулевой задержки на горячем пути** — события геймификации отправляются "огонь и забудь" из конвейера запросов и никогда не блокируют ответ LLM.

---

## Обзор

### Назначение

Повышение вовлеченности и удержания пользователей за счет видимого прогресса (XP, уровни, значки), социального доказательства (таблицы лидеров) и экономических стимулов (обмен токенами, вознаграждения за приглашения).

### Область применения

| Функция           | Описание                                                     |
| ----------------- | --------------------------------------------------------------- |
| XP & Уровни       | Получение XP за каждое действие; повышение уровня по полиномиальной кривой           |
| Значки            | 20+ достижений в 5 категориях с 4 уровнями редкости        |
| Серии           | Отслеживание ежедневного активного использования с текущей/наибольшей серией         |
| Таблицы лидеров      | Глобальные, еженедельные, ежемесячные, таблицы лидеров по обмену токенами и вкладом |
| Обмен токенами     | Передача кредитов между пользователями через двойную запись в журнале          |
| Приглашение & Погашение   | Реферальные коды с хэшированием SHA-256                      |
| Серверы сообщества | Федерация с внешними экземплярами OmniRoute                      |
| Анти-чит        | Серверное вычисление очков, ограничение скорости, обнаружение аномалий по z-оценке   |

### Принципы проектирования

1. **Локальный приоритет** — все состояние в SQLite, внешние сервисы не требуются.
2. **Неблокирующий** — события отправляются "огонь и забудь"; путь ответа LLM никогда не задерживается логикой геймификации.
3. **Серверная авторитетность** — XP вычисляется только на сервере; клиенты не могут увеличивать баллы.
4. **Соблюдение конфиденциальности** — участие в таблицах лидеров является необязательным; пользователи могут скрыть свой профиль.
5. **Готовность к федерации** — серверы сообщества могут отправлять баллы через подписанный API; синхронизация выполняется перезаписью, а не добавлением.

## Архитектура

### Высокоуровневый поток

```
Запрос клиента
  → /v1/chat/completions
    → handleChatCore()                      [open-sse/handlers/chatCore.ts]
      → ... (существующий конвейер) ...
      → ответ от сервера отправлен клиенту
      → setImmediate (огонь и забудь):
        → emitGamificationEvent()           [src/lib/gamification/events.ts]
          → awardXp()                       [src/lib/gamification/xp.ts]
          → updateStreak()                  [src/lib/gamification/streaks.ts]
          → evaluateBadges()                [src/lib/gamification/badges.ts]
          → updateLeaderboard()             [src/lib/gamification/leaderboard.ts]
          → checkAnomalies()                [src/lib/gamification/antiCheat.ts]
```

Модуль генерации событий является единственной точкой интеграции. `chatCore.ts` вызывает `emitGamificationEvent()` после отправки ответа; модуль событий рассылает информацию по подсистемам XP, серии, значки, таблицы лидеров и анти-чит.

### Граф зависимостей модулей


## Система XP / Уровней

**Файл:** `src/lib/gamification/xp.ts`

### Кривая уровней

Количество XP, необходимых для достижения уровня `n`, следует полиномиальной кривой:

```
xp_for_level(n) = floor(100 * n^1.5)
```

| Уровень | XP до следующего | Накопленный XP | Титул    |
| ------- | ---------------- | -------------- | -------- |
| 1       | 100              | 100            | Новичок  |
| 5       | 1,118            | 2,415          | Новичок  |
| 10      | 3,162            | 10,523         | Исследователь |
| 25      | 12,500           | 86,024         | Исследователь |
| 50      | 35,355           | 345,529        | Эксперт   |
| 75      | 64,952           | 948,683        | Мастер    |
| 100     | 100,000          | 2,050,000      | Легенда   |

### Титулы

| Диапазон уровней | Титул    |
| ---------------- | -------- |
| 1 – 9            | Новичок  |
| 10 – 24          | Исследователь |
| 25 – 49          | Эксперт   |
| 50 – 74          | Мастер    |
| 75 – 100         | Легенда   |

### Награда XP

| Действие            | XP  | Описание                                                  |
| ------------------- | --- | --------------------------------------------------------- |
| `request`           | 1   | За успешный запрос к LLM                                  |
| `provider_switch`   | 5   | Переключение на другого провайдера                        |
| `combo_create`      | 10  | Создание новой комбинации конфигураций                    |
| `combo_use`         | 2   | Использование комбинации (за каждое попадание)           |
| `badge_earned`      | 25  | Получение любого значка                                   |
| `streak_milestone`  | 15  | Достижение этапа серии (7, 14, 30, 60, 90, 180, 365)      |
| `referral`          | 50  | Успешное привлечение нового пользователя                 |
| `token_share`       | 5   | Обмен токенами с другим пользователем                     |
| `daily_login`       | 3   | Первый запрос в день                                      |
| `model_diversity`   | 3   | Использование модели, не использовавшейся за последние 7 дней |
| `compression_use`   | 2   | Использование сжатия запроса                               |
| `skill_use`         | 2   | Выполнение навыка через MCP                              |

### Поток наград

```typescript
export async function awardXp(
  apiKeyId: string,
  action: XpAction,
  metadata?: Record<string, unknown>
): Promise<{ xp: number; level: number; title: string; levelUp: boolean }>;
```

1. Найдите `XP_REWARDS[action]`, чтобы получить количество XP.
2. Пройдите через `checkRateLimit()` (анти-чит: максимум 1000 XP/мин на ключ).
3. Откройте транзакцию:
   - Прочитайте строку `user_levels`.
   - Добавьте XP; пересчитайте уровень через `levelFromXp(totalXp)`.
   - Если уровень изменился, установите `levelUp = true`.
   - Обновите строку `user_levels`.
   - Вставьте в `xp_audit_log`.
4. Верните результат. Вызывающая сторона обрабатывает уведомления.

### Помощник: `levelFromXp(totalXp)`

Итерация уровней 1..100, суммирование `xp_for_level(n)`, пока накопленный XP не превысит `totalXp`. Возвращает наивысший уровень, чей порог достигнут.
Это O(100) — допустимо, так как уровни ограничены 100.

## Система значков

**Файл:** `src/lib/gamification/badges.ts`

### Категории

| Категория      | Описание                          | Примеры значков                    |
| -------------- | --------------------------------- | --------------------------------- |
| `usage`        | Достижения по объему использования | Первый запрос, 1K запросов, 100K  |
| `sharing`      | Обмен токенами и привлечение       | Первый обмен, Щедрый (10 обменов) |
| `contribution` | Вклад в сообщество                | Создатель комбинаций, Исследователь провайдеров |
| `streak`       | Последовательность использования   | Воин недели, Месячный преданный    |
| `rare`         | Скрытые достижения                | Ранний адаптер, Сообщитель об ошибках |

### Редкость

| Редкость     | Цвет  | Подсказка вероятности |
| ------------ | ----- | --------------------- |
| `common`     | Серый | Большинство пользователей |
| `uncommon`   | Зеленый | Активные пользователи |
| `rare`       | Синий | Преданные пользователи |
| `legendary`  | Золотой | Топ 1%                |

### Типы критериев

| Тип            | Поле         | Описание                                      |
| -------------- | ------------ | --------------------------------------------- |
| `action_count` | `count`      | Выполните действие N раз (например, 1000 запросов) |
| `streak`       | `days`       | Поддерживайте серию N последовательных дней   |
| `unique_count` | `field`, `n` | Используйте N уникальных значений (например, 10 разных моделей) |
| `rank`         | `scope`, `n` | Достигните ранга N в области лидерборда      |
| `first`        | —            | Будьте первым, кто выполнил действие          |
| `hidden`       | (разное)     | Критерий не показывается до получения         |

Определения значков хранятся в `badge_definitions` в виде JSON `criteria`:

```json
{
  "type": "action_count",
  "action": "request",
  "count": 1000
}
```

### Поток оценки

```
emitGamificationEvent(event)
  → evaluateBadges(apiKeyId, event)
    → getBadgeDefinitions()           # все определения
    → getUserBadges(apiKeyId)         # уже полученные (пропустить)
    → для каждого неполученного значка:
       → matchesCriteria(badge, event, userState)
       → если совпадение: awardBadge(apiKeyId, badgeId)
         → вернуть полезную нагрузку уведомления
```

Оценка **событийно-ориентирована** — она запускается после каждого игрового события, но проверяет только значки, чьи `criteria.type` соответствуют действию события. Это обеспечивает быструю оценку (< 5 мс для большинства событий).

### `matchesCriteria(badge, event, userState)`

| Тип критерия  | Проверка                                          |
| -------------- | -------------------------------------------------- |
| `action_count` | `getActionCount(apiKeyId, action) >= count`        |
| `streak`       | `getCurrentStreak(apiKeyId) >= days`               |
| `unique_count` | `getUniqueCount(apiKeyId, field) >= n`             |
| `rank`         | `getRank(apiKeyId, scope) <= n`                    |
| `first`        | Нет предыдущих записей `xp_audit_log` для этого типа действия |
| `hidden`       | Делегирует соответствующую подпроверку             |

## Streak Tracker

**File:** `src/lib/gamification/streaks.ts`

### Модель данных

Streaks хранятся в таблице `key_value` (общая служебная таблица) под
пространственными ключами:

| Ключ                          | Значение                         | Описание           |
| ----------------------------- | -------------------------------- | ------------------ |
| `gamification:streak:{keyId}` | `{current},{longest},{lastDate}` | Данные активного стрика |

### Логика

```typescript
export async function updateStreak(
  apiKeyId: string
): Promise<{ current: number; longest: number; milestone: boolean }>;
```

1. Прочитать запись о стрике из `key_value`.
2. Разобрать `{current}`, `{longest}`, `{lastDate}` (строка даты в формате ISO).
3. Если `lastDate === today` — нет изменений (уже учтено сегодня).
4. Если `lastDate === yesterday` — увеличить `current`; обновить `longest`, если нужно.
5. Если `lastDate < yesterday` — сбросить `current = 1` (стрик прерван).
6. Записать обновлённую запись.
7. Проверить достижения: 7, 14, 30, 60, 90, 180, 365 дней. Если достижение преодолено, установить
   `milestone = true` (вызывающая сторона награждает XP и проверяет бейджи).

### Краевые случаи

- **Часовой пояс**: стрики используют даты в формате UTC (`new Date().toISOString().slice(0, 10)`).
  Это сделано намеренно — единый часовой пояс предотвращает манипуляции с помощью
  перехода между часовыми поясами.
- **Новые пользователи**: нет записи о стрике; первый запрос создаёт её с
  `current=1, longest=1, lastDate=today`.
- **Множественные запросы в день**: только первый запрос в UTC день
  увеличивает стрик.

## Leaderboard

### Области

| --------------- | ------- | --------------------------------------------- |
| `global`        | `all`   | Всего XP накоплено                          |
| `weekly`        | `week`  | XP заработано в текущей UTC неделе (Пн-Вс)  |

| `contributions` | `all`   | Комбо создано + провайдеры использованы + навыки использованы |

### Вычисление ранга

Ранги **вычисляются при чтении**, а не хранятся. Это предотвращает устаревшие данные о рангах
и избавляет от необходимости в периодических заданиях на пересчёт рангов.

```typescript
export async function getLeaderboard(
  scope: LeaderboardScope,
  period: string,
  limit: number,
  offset: number
): Promise<{ entries: LeaderboardEntry[]; total: number }>;
```

Шаблон запроса:

```sql
SELECT api_key_id, score,
       RANK() OVER (ORDER BY score DESC) as rank
FROM leaderboard
WHERE scope = ? AND period = ?
ORDER BY score DESC
LIMIT ? OFFSET ?
```

### Вращение периодов

Лидерборды по неделям и месяцам автоматически вращаются:

1. **Архивирование**: при переходе на новый период, текущие записи копируются в
   `leaderboard_archive` с меткой периода.
2. **Сброс**: удаляются записи для истёкшего периода.
3. **Триггер**: проверяется при каждом вызове `updateLeaderboard()`; первый запрос
   нового периода запускает вращение.

Это гарантирует, что еженедельные лидерборды сбрасываются каждый понедельник в 00:00 UTC, а ежемесячные — в 1-е число каждого месяца.

### Обновления в реальном времени через SSE

**Endpoint:** `GET /api/gamification/stream`

```
Клиент → GET /api/gamification/stream
  → Установлено соединение SSE
  → Сервер отправляет снимок топ-10 лидерборда сразу
  → Каждые 5 секунд: отправляет обновлённый топ-10, если изменился
  → Каждые 15 секунд: отправляет heartbeat (": heartbeat\n\n")
  → Клиент отключается → очистка (удаление слушателя)
```

Формат событий:

```
event: leaderboard
data: {"scope":"global","entries":[...]}

event: leaderboard
data: {"scope":"weekly","entries":[...]}

: heartbeat
```

Менеджер SSE отслеживает подключённых клиентов по областям и отправляет обновления
только в случае реальных изменений данных лидерборда с момента последней отправки.

## Токены

**Файл:** `src/lib/gamification/sharing.ts`

### Двойная запись

Каждый перевод создает две строки в `token_ledger`:

| Строка  | `from_key_id` | `to_key_id` | `amount` |
| ------ | ------------- | ----------- | -------- |
| Дебет  | отправитель   | получатель  | +amount  |
| Кредит | получатель    | отправитель | -amount  |

Подождите — соглашение:

| Строка   | `from_key_id` | `to_key_id` | `amount` | Значение            |
| ------- | ------------- | ----------- | -------- | ------------------- |
| Отправка | отправитель   | получатель  | +amount  | Исходящий поток от отправителя |
| Получение | получатель    | отправитель  | +amount  | Входящий поток к получателю  |

Баланс вычисляется как:

```sql
SELECT
  COALESCE(SUM(CASE WHEN to_key_id = ? THEN amount ELSE 0 END), 0)
  - COALESCE(SUM(CASE WHEN from_key_id = ? THEN amount ELSE 0 END), 0)
  AS balance
FROM token_ledger
WHERE from_key_id = ? OR to_key_id = ?
```

### Поток передачи

```typescript
export async function transferTokens(
  fromKeyId: string,
  toKeyId: string,
  amount: number,
  idempotencyKey: string
): Promise<{ success: boolean; balance: number }>;
```

1. **Валидация**: `amount > 0`, `fromKeyId !== toKeyId`.
2. **Идемпотентность**: проверьте, существует ли `idempotency_key` уже в журнале.
   Если да, верните кэшированный результат.
3. **Транзакция** (одна транзакция SQLite):
   a. Вычислите баланс отправителя.
   b. Если `balance < amount`, прервать (недостаточно средств).
   c. Вставить строку отправки (`from=sender, to=receiver, amount`).
   d. Вставить строку получения (`from=receiver, to=sender, amount`).
4. **Ограничение скорости**: проверьте скорость передачи для отправителя (максимум 10 передач/мин).
5. **Событие**: инициировать событие `token_share` для геймификации XP + оценки значка.
6. Вернуть `{ success: true, balance: newBalance }`.

### Ограничение скорости

- Максимум 10 передач в минуту на API-ключ.
- Максимум 10,000 токенов на одну передачу.
- Максимум 100,000 токенов передается в день на API-ключ.

## Пригласить и обменять токены

**Файл:** `src/lib/gamification/invites.ts`

### Формат кода

- **Код**: 8-значный алфавитно-цифровой (например, `A3K9-X7M2`), удобочитаемый,
  отображается пользователю.
- **Токен**: 32-байтовый случайный токен, хранится как SHA-256 хэш. Используется для
  программного обмена (например, URL-ссылки).

### Хранение

| Столбец       | Значение                        |
| ------------ | ---------------------------- |
| `code`       | `A3K9X7M2` (уникальный, индексированный) |
| `token_hash` | SHA-256(raw_token)           |

Необработанный токен возвращается пользователю ровно один раз при создании. OmniRoute
никогда не хранит или не отображает его снова — только хэш сохраняется.

### Предотвращение самоссылок

Когда пользователь обменивает код, система проверяет:

1. Код принадлежит другому `api_key_id`.
2. Обменивающий пользователь ранее не обменивал ни один код от того же реферера (соединения на `invite_tokens` + журнал обмена).

Если любой из проверок не удается, обмен отклоняется с ясным сообщением об ошибке.

### Срок действия и ограничения

- `max_uses` по умолчанию: 10 (настраивается при создании).
- `expires_at` по умолчанию: 30 дней с момента создания.
- Просроченные или исчерпанные коды возвращают HTTP 410 Gone.

## Федерация сообщества серверов

**Файл:** `src/lib/gamification/servers.ts`

### Подключение

Сообщество сервера регистрируется через пригласительный токен, выданный удаленным сервером. Локальная инстанция:

1. Получает пригласительный токен (например, вставленный в панель управления).
2. Вызывает `POST /api/gamification/federation/leaderboard` на удаленном сервере для проверки токена и получения текущего рейтинга.
3. Сохраняет запись сервера с `status: connected`.

### Синхронизация модели

Федерация использует **синхронизацию перезаписи**, а не аддитивную:

```
Локальная инстанция                Сообщество сервера
     │                              │
     ├── отправить очки ───────────────►│  POST /federation/score
     │   { api_key_id, score }      │  (сервер проверяет хеш токена)
     │                              │
     ├── получить рейтинг ─────────►│  GET /federation/leaderboard
     │◄── топ-N записей ────────────┤  (перезаписывает локальный кэш)
     │                              │
     └── проверка состояния ─────────────►│  GET /federation/health
         (каждые 60 секунд, таймаут 5 секунд)    │
```

### Аутентификация

Запросы федерации включают:

```
Authorization: Bearer <raw_token>
X-Federation-Version: 1
```

Удаленный сервер хеширует токен и ищет соответствующую строку `community_servers`. Это предотвращает передачу сохраненного хеша.

### Мониторинг состояния

Каждая запись сервера отслеживает:

| Поле        | Описание                            |
| ----------- | -------------------------------------- |
| `status`    | `connected`, `degraded`, `unreachable` |
| `last_sync` | ISO временная метка последней успешной синхронизации  |
| `failures`  | Последовательные сбои проверки состояния      |

После 5 последовательных сбоев статус меняется на `unreachable`, и синхронизация приостанавливается до успешной ручной проверки состояния.

## Анти-Чит

**Файл:** `src/lib/gamification/antiCheat.ts`

### Серверное подсчет очков

Все расчеты XP происходят в `src/lib/gamification/xp.ts`. Клиенты никогда не отправляют очки — они отправляют действия, и сервер вычисляет XP. Столбец `leaderboard.score` доступен только для серверного кода.

### Ограничение скорости

| Ограничение                 | Значение   | Область        |
| --------------------- | ------- | ------------ |
| Максимальные XP в минуту     | 1,000   | На API ключ  |
| Максимальные передачи в минуту | 10      | На API ключ  |
| Максимальная сумма передачи   | 10,000  | На передачу |
| Максимальные ежедневные передачи   | 100,000 | На API ключ  |

Ограничения скорости используют скользящее окно в памяти (такой же шаблон, как и `RateLimitManager` в `open-sse/services/`). При перезапуске процесса переходит на счетчики, поддерживаемые SQLite.

### Обнаружение аномалий Z-Score

Для каждого API ключа система поддерживает скользящее окно 7 дней XP, заработанных за час. При каждом награждении XP:

1. Вычислите текущую часовую ставку XP пользователя.
2. Вычислите среднее значение и стандартное отклонение популяции.
3. Вычислите `z = (user_rate - mean) / stddev`.
4. Если `z > 3.0` (3 стандартных отклонения), пометить как аномалию.

Аномалии записываются в `xp_audit_log` с `action = 'anomaly_detected'` и отображаются на панели администратора.

### Аудит

Каждое награждение XP, передача, получение значка и обнаружение аномалии записываются в `xp_audit_log` с:

| Поле        | Описание                                    |
| ------------ | ---------------------------------------------- |
| `api_key_id` | Кто                                            |
| `action`     | Что произошло (xp_award, transfer, anomaly, …) |
| `xp_awarded` | Сумма (0 для не-XP событий)                   |
| `metadata`   | JSON с контекстом (тип действия, цель, …)     |
| `created_at` | Когда (ISO 8601)                                |

Администраторы могут запрашивать полный аудит через `GET /api/gamification/anomalies`.

| -------------------- | ------------------------------------- |

| `provider.switch`    | Изменен провайдер (переключение комбо считается) |
| `combo.created`      | Новая конфигурация комбо сохранена    |
| `combo.used`         | Целевая конфигурация комбо успешно достигнута |
| `badge.earned`       | Оценка значка нашла совпадение        |
| `streak.milestone`   | Преодолена пороговая серия             |
| `transfer.sent`      | Передача токенов завершена            |
| `referral.redeemed`  | Пригласительный код успешно использован |
| `compression.used`   | Применено сжатие запроса               |
| `skill.executed`     | Выполнение навыка завершено           |
| `model.first_use`    | Модель не использовалась в течение последних 7 дней |

### Гарантия неблокировки

Паттерн `setImmediate` + `.catch(() => {})` обеспечивает:

1. Ответ полностью отправлен до запуска геймификации.
2. Ошибки геймификации никогда не отображаются клиенту.
3. Обработка событий выполняется в следующем микротаске, а не встроена.

## Безопасность

### Модель угроз

| Угроза                   | Снижение рисков                                                          |
| ------------------------ | ------------------------------------------------------------------- |
| Надувание рейтинга          | Вычисление XP только на сервере; клиенты отправляют действия, а не рейтинги |
| Повторные атаки           | Ключи идемпотентности для переводов; аудит-журнал без дублирования                      |
| Мошенничество при переводе           | Двойная запись в бухгалтерском учете; атомарные транзакции; ограничение скорости               |
| Самоссылка            | Проверка `api_key_id` при погашении                              |
| Манипуляции с таблицей лидеров | Обнаружение аномалий по Z-оценке; панель аномалий администратора                  |
| Кража токенов федерации   | Хранение в виде SHA-256 хеша; исходный токен показывается только один раз                   |
| Силами перебора коды приглашения | Ограничение скорости на конечной точке погашения; 8-символьная энтропия                |
| XSS в отображаемых именах     | Отображаемые имена очищаются; записи в таблице лидеров экранируются                |
| Атаки на тайминг хешей | `crypto.timingSafeEqual` для сравнения хешей токенов                  |

### Требования к аутентификации

- **Публичный** (без аутентификации): `GET /leaderboard`, `GET /stream` (только для чтения
  таблицы лидеров).
- **Требуется API-ключ**: все операции записи, профиль, переводы, приглашения.
- **Только администратор**: панель аномалий, просмотр аудит-журнала.
- **Федерация**: отдельный путь аутентификации с использованием исходного токена в заголовке `Authorization`,
  который проверяется против сохраненного SHA-256 хеша.

## Будущие возможности

- **Сезонные события**: временные наборы значков и сезонные таблицы лидеров.
- **Командные таблицы лидеров**: группировка пользователей по организации или комбо.
- **Множители XP**: увеличение XP во время промо-периодов.
- **Обмен достижениями**: генерация обмениваемых карточек значков (OpenGraph изображения).
- **Мобильные push-уведомления**: вебхук-оповещения о событиях значков/уровней.
- **API таблиц лидеров**: публичный API для интеграции с третьими лицами.
