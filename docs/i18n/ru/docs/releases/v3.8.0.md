# OmniRoute v3.8.0 — Примечания к выпуску

**Дата выпуска**: 2026-05-15
**Основные изменения**: 7 новых функций + переработка UX для уровней + 10 публичных навыков AI-агентов.

## Новые функции

### MCP умный текстовый фильтр (Задача 1)

Движок сжатия, специально разработанный для избыточных выходных данных MCP (снимки браузера, деревья доступности). Сворачивает ≥30 повторяющихся соседних строк в заголовок + сводку

- хвост, сохраняет `[ref=eXX]` якоря, необходимые для Playwright/computer-use,
  жестко обрезает слишком большой текст с подсказкой навигации.

* Новый движок: `open-sse/services/compression/engines/mcpAccessibility/`
* Настройки: `compression.mcpAccessibility` (миграция 056)
* Ожидаемые сбережения: 60-80% на результатах инструментов снимков браузера

### Публичные навыки AI-агентов (Задача 2)

Десять манифестов `SKILL.md` под `skills/omniroute*/` опубликованы для внешних AI-агентов (Claude Desktop, ChatGPT, Cursor, Cline) для использования через сырые URL-адреса GitHub.
Нулевая трение при подключении: просто скажите своему агенту, чтобы он извлек один URL и начал маршрутизацию.

### Отдельный системный трей (Задача 3)

Пользователи CLI теперь получают значок системного трея без необходимости в Electron. Windows использует PowerShell `NotifyIcon` (без новых бинарных файлов, совместимых с AV). macOS/Linux используют форк `systray2`, установленный лениво в `~/.omniroute/runtime/`. Включает кроссплатформенный автозапуск (LaunchAgent / `.desktop` / реестр).

- Новый флаг: `omniroute --tray`
- Новая команда: `omniroute config tray <enable|disable>`
- Новые модули: `bin/cli/tray/`

### CLI токен machine-ID (Задача 4)

`HMAC-SHA256(machine-id, salt)` → токен, сравниваемый в постоянном времени, отправляется через заголовок `x-omniroute-cli-token`. Позволяет командам CLI аутентифицироваться локально без JWT/пароля.

- Принимается только на loopback хосте + белых списках только для чтения маршрутов
- Вращение соли через переменную окружения `OMNIROUTE_CLI_SALT`
- Возвращается к `~/.omniroute/machine-id` (0600), если `node-machine-id` не удается
- Документация: `docs/security/CLI_TOKEN.md`

### Уровни защиты маршрутов (Задача 5)

Все API-маршруты классифицированы на 5 уровней (`public`, `read-only`, `protected`, `always`, `local-only`). Маршруты, способные к спавну (MCP, инструменты CLI, колбэки OAuth, MITM, навыки), обеспечивают loopback хост+происхождение даже с действительным JWT — утерянный JWT через туннель больше не может инициировать спавн дочернего процесса.

- Новый модуль: `src/lib/auth/routeGuard.ts`
- Новое жесткое правило №15 в `CLAUDE.md`
- Документация: `docs/security/ROUTE_GUARD_TIERS.md`

### Caveman SHARED_BOUNDARIES (Задача 6)

Промпты Caveman (LITE/FULL/ULTRA) теперь встраивают общую граничную клаузулу, инструктирующую LLM сохранять кодовые блоки, пути к файлам, команды, ошибки и URL-адреса точными, а также писать предупреждения о безопасности и подтверждения необратимых действий обычным прозаическим текстом.

- Новая константа: `SHARED_BOUNDARIES` в `open-sse/services/compression/outputMode.ts`
- Все 6 языков × 3 интенсивности обновлены
- Исправлен порядок проверки `alreadyApplied` (должен предшествовать `shouldBypassCavemanOutputMode`)

### Динамический установщик SQLite (Задача 7)

Пятиступенчатая цепочка разрешения драйверов:
`bundled better-sqlite3` → `runtime-installed better-sqlite3` → `lazy install` → `node:sqlite (Node ≥22.5)` → `bundled sql.js (WASM)`. Каждый нативный бинарный файл проверяется на соответствие ожидаемым магическим байтам платформы (ELF / Mach-O / PE) перед загрузкой. Решает проблему ошибки Windows EBUSY при глобальных обновлениях, когда OmniRoute работает.

- Новые скрипты: `scripts/postinstall.mjs`, `bin/cli/runtime/`
- Каталог времени выполнения: `~/.omniroute/runtime/`
- Новый помощник: `src/lib/db/core.ts::ensureDbInitialized()`
- Документация: `docs/ops/SQLITE_RUNTIME.md`

### Маркетинг и онбординг для уровней 1/2/3 (Задача 8)

Раздел README "Почему OmniRoute?" улучшен с ASCII-диаграммой уровней и таблицей сравнения. Новый шаг `/dashboard/onboarding/steps/TierTour.tsx` показывает поток уровней при первом запуске с SVG-активами светлой/темной темы. Главный дашборд получает виджет "Покрытие уровней" с CTA для пустого состояния.

- Новые активы: `images/tier-flow-light.svg`, `images/tier-flow-dark.svg`
- Новая документация: `docs/marketing/TIERS.md`

## Неработающие изменения

`getDbInstance()` теперь требует, чтобы `ensureDbInitialized()` был выполнен сначала.
Оркестратор запуска сервера автоматически ожидает его. В тестах или пользовательских встраиваниях вызовите `await ensureDbInitialized()` перед любым импортом `src/lib/db/*`, который инициирует доступ к экземпляру.

## Руководство по миграции

Для существующих установок:

```bash
npm install -g omniroute@3.8.0
omniroute setup   # опционально — повторно запускает онбординг для показа нового тура по уровням
```

Токены CLI производятся автоматически; миграция не требуется.
Для включения трея: `omniroute --tray` или `omniroute config tray enable`.

Для разработчиков, внедряющих OmniRoute:

- Замените прямые вызовы `getDbInstance()` на `await ensureDbInitialized(); getDbInstance()`
```
